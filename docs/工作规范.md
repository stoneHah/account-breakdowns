# 工作规范

本规范约束这个资料库怎么写、收到什么程度、什么可以公开。它不附带采集程序。已收录账号的结论只写在该账号自己的 `analysis.md`，这里只用一两句例子说明分级，不重复整篇分析。

## 1. 证据分级

每条对外结论带一个等级。四个等级不要混写。

| 等级 | 含义 | 例子 |
|---|---|---|
| 事实 | 公开接口字段、本地测量，或关键帧上可读的字和画面 | 三条已观看样本的 ffprobe 时长是 46.833 秒、15.033 秒、96.767 秒 |
| 推断 | 有限样本归纳出的表现。全量作品或作者源码还没有证实它 | 由简介、标题和三条样本看出的选题与画面习惯 |
| 用户补充 | 用户本人的判断或背景。写下时间。它仍是用户的话 | 2026-11-15 09:31（北京时间），用户判断该号作品是代码生成 |
| 待核查 | 已经看到疑点，这一轮不下判断 | 资料页 27 条与列表 26 条相差 1 条；画面「洛水」与文案「洺水」 |

用户补充保持原意。代码生成记为「用户确认/判断，未取得作者工程源码独立核实」。在看到作者工程源码之前，文档停在这个等级，不改写成某一软件、某一框架或某种全量制作手段已经核实。

当前这种抽样，够用来写风格和选题。它不够用来证明账号的全部制作方法。

史实用字、地名、年代若对不上，记为待核查。拆解档案不做历史审定。印章、片名在相邻画面之间切换时，写下看见了什么，以及衔接、残留或钩子这几种可能；静帧分不出的，就停在待核查。

原稿里的「实证」与这里的「事实」是同一等级。

## 2. 抽样与成本

默认先做低成本抽样，并在 `research-process.md` 写明边界：

- 累计接口请求以 6 次为上限（含入口那一条）。
- 作者资料 1 次。
- 作品列表最多 2 页。
- 下载观看的代表作不超过 3 条：入口作品、样本里互动相对高且选题不同的一条、接近中位数的普通样本。
- 不翻评论，不把账号历史翻完。

列表到了 `has_more=0`，只说明当时这个列表接口没有下一页。资料页作品数和列表条数不一致时，差额标成待核查，统计写明「只基于本样本」。

代表作的时长用本地探测（如 ffprobe）为准。观看工具若给出另一个时长，不沿用。

抽帧建议取 0、2、5、10、20、30 秒和末尾，且不超过真实时长。片尾若是黑场，联系表用最后一帧还能看见画面的时间，并注明黑场大约从哪里开始。没抽到的时段，不写成「已经看见」或「画面里没有」。

接口次数、成败、时间和费用是否核实，记在该快照的 `api-usage.json`。单价说明不是账单。实际费用没核对时写成未核实。

小qu档案馆这一次的实际用量见 [api-usage.json](../accounts/douyin/xiaoqu-danganguan/snapshots/2026-11-15/api-usage.json)：4 次请求全部成功，没有打满 6 次上限，实际费用未核实。

## 3. 时间

对外时间统一用北京时间（Asia/Shanghai），写明日期和钟点。采集窗口、用户补充、发布时间用同一时区。不要在同一篇里混进未标注的其他时区。

互动数字属于采集当时。之后会变，引用时带上快照时间。

## 4. 互动数字

赞、评、藏、转只描述互动。播放、完播和收益各自需要自己的公开字段。没有这些字段时，不从赞推算播放或收入。

同一次采集里，作品发布时间有先有后，到采集为止能够累积互动的时间并不相同。中位数、排序和栏目分组都只作描述。短片的赞高于某条长片，是两列数字并列，不写成片长或栏目造成了这个差别。

## 5. 素材版权与安全

仓库是公开的。写成「已经提交」之前，再扫一遍文本和关键帧。

可以入库：

- 公开作品 URL、公开账号 URL
- 公开昵称、公开账号 ID
- 发布时间、时长、画幅
- 赞、评、藏、转和由此算出的样本统计
- 短标题或公开钩子
- 少量分析用关键帧，附原作品链接和归属

不入库：

- 接口密钥、会话凭据、请求头、响应头
- 带签名或过期参数的播放地址
- 原始接口响应、原视频
- 商务联系方式、即时通讯账号、邮箱、电话和其他私人资料
- 完整口播长文、整段编年正文
- 本机路径、临时压缩包、上传目录

关键帧在 `keyframes/README.md` 和 `sources.md` 写明截取自哪一条公开作品。权利归原作者和平台。资料库不宣称这些画面是原创资产，也不把它们放进 MIT 或其他开源许可证。仓库根目录不设覆盖全部文件的许可证。

`.gitignore` 用来挡住 `.env`、原视频、`raw/` 和临时压缩包。脱敏后的 `snapshot.json`、`works.json` 和 `api-usage.json` 属于本规范要保留的文件，不要被忽略规则排除。

## 6. 入库前

1. 结论只在账号的 `analysis.md` 写完整一次。概况页和快照页用链接指向它。
2. 作品表、快照统计和文中的数字要能对上。偶数条的中位数取排序后中间两条的平均。
3. 跑 `python3 scripts/check_archive.py`。脚本只读本仓库，无第三方依赖，不访问网络。
4. 修订记入该账号的 `revision-log.md`。
