# 通用账号拆解模板

新建一个账号时，复制下面的目录，替换平台、简称和日期。本模板只规定文档怎么摆，不附带采集程序。分级、抽样上限、北京时间、互动口径、版权和安全见 [工作规范](../docs/工作规范.md)。

已填好的实例是 [小qu档案馆 / 2026-11-15](../accounts/douyin/xiaoqu-danganguan/README.md)。那是一条真实档案，不要把它复制成另一个账号。

```
accounts/{平台}/{账号简称}/
  README.md                 概况、链接、阅读顺序
  analysis.md               唯一的完整分析
  research-process.md       调研过程与样本选择
  sources.md                来源与归属
  revision-log.md           修订记录
  snapshots/{YYYY-MM-DD}/
    README.md               这一天的文件索引
    snapshot.json           脱敏账号与样本统计
    works.csv
    works.json
    api-usage.json          次数、成败、费用是否核实
    keyframes/
      README.md
      01-contact.jpg
```

## README.md

- 平台、公开昵称、公开账号 ID、主页链接
- 快照时间（北京时间）和指向 `snapshots/{日期}/` 的链接
- 阅读顺序：分析、调研过程、作品表、关键帧、来源、修订
- 指向工作规范的相对链接

概况只摘数字和入口。完整结论留在 `analysis.md`。

## research-process.md

写清任务是单条还是账号抽样、请求上限和实际次数、有没有看评论、看了哪几条、每条真实时长、抽帧时间点，以及入库时删掉了什么。样本选择单独成节，说明入口条、相对高互动条和普通样本各是哪一条、为什么选它。

## analysis.md

建议顺序：

1. 观点，带证据等级。
2. 账号与样本数字（事实），并写明样本边界。
3. 已交叉核验的样本。每条给作品链接、ffprobe 时长、关键帧相对路径。
4. 本轮结论停在哪里。

文中使用「事实 / 推断 / 用户补充 / 待核查」。用户对制作方式的判断，写成「用户确认/判断，未取得作者工程源码独立核实」。

## 快照白名单

`snapshot.json`、`works.csv`、`works.json` 可以包含：

- 公开账号 URL、公开作品 URL
- 公开昵称、公开账号 ID
- 赞、评、藏、转
- 时长、发布时间、画幅
- 短标题或公开钩子
- 采集时间、时区、采集渠道名称、请求次数、聚合统计

`api-usage.json` 记录渠道名称、次数、成败、北京时间和实际费用是否核实。

同一快照目录里的统计与 `works.csv` 保持可重算。偶数条中位数取中间两条的算术平均。资料页条数和列表条数不同时，把差额写成待核查。

## 关键帧

每张联系表在 `keyframes/README.md` 写上对应作品、正式链接、抽帧时间点和真实时长。表头可以标作品 ID 和时长，便于对照。

画面中的角色、字幕、地图和标题来自原作品。文件说明里写明权利归原作者和平台，本档案不取得再授权。

## revision-log.md

每次更正数字、改证据等级或增删公开材料，记一条日期。更正写明改前、改后和依据。
